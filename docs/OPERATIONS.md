# Развёртывание и стенд

## Сервер

JDK 21, FFmpeg, отдельный пользователь `busradio`. Скопировать JAR в `/opt/busradio`, properties в `/etc/busradio`, состояние хранить в `/var/lib/busradio`. Задать абсолютный `server.data=/var/lib/busradio/server`. Файл `/etc/busradio/server.env` содержит `BUSRADIO_ADMIN_TOKEN=...`, права 0600 root:root; systemd читает его до смены пользователя. Создать ключ командой `java -jar busradio.jar token`. Не копировать токены из demo в рабочую среду.

Unit-файлы в `deploy/` — образцы; проверить фактические пути JDK, права, наличие FFmpeg. Перед сервисом поставить HTTPS reverse proxy с лимитом тела до 256 MiB и таймаутами для загрузки. В Интернет не выставлять чистый HTTP. Админский интерфейс дополнительно ограничить VPN/ACL. Настроить резервное копирование после корректной остановки сервера: JSON-файлы и каталог media нужны вместе. Проект не заменяет аудит безопасности перед публичным запуском.

## Бортовой компьютер

Практическая цель этого backend — 64-битная Raspberry Pi OS и Pi 3/4/Zero 2 с JDK 21. Собрать `mvn -Ppi clean verify`. Обычный переносимый JAR не содержит Pi4J. Pi4J 3.0.4/GpioD использует gpiochip0; проверить `gpiodetect`, права пользователя на `/dev/gpiochip0`, совместимость ядра и библиотек по официальной документации. Pi4J не должен занимать GPIO4.

Создать независимое питание SBC, автомобильную защиту питания и корректное завершение при выключении. Бортовая сеть 12/24 В требует подходящего DC/DC, защиты от импульсов и гальванически развязанного/согласованного входа зажигания. **Не подавать напряжение бортсети на GPIO.** Ночное скачивание невозможно, если SBC физически обесточен после рейса: нужно питание на стоянке или контролируемое пробуждение.

В текущей разводке используются BCM-номера: 17 — зажигание (HIGH=рейс), 22 — приоритетное приглушение/PA (HIGH=остановить проигрывание), 27 — индикатор воспроизведения. Входы — только безопасные 3.3-вольтовые сигналы после согласования; активный уровень и внешние подтяжки проверить на стенде. Обычный Pi4J-провайдер не создаёт FM-несущую.

USB/GNSS-приёмник подключить к gpsd. Указать `position.mode=gpsd`, `gpsd.host=127.0.0.1`, `gpsd.port=2947`. Клиент использует TPV time/mode/lat/lon/speed/track/epx/epy. Отсутствие приемлемой оценки точности трактуется консервативно: нет георекламы. Входы GPSD и GPIO не были физически проверены в среде разработки.

Wi-Fi подключает NetworkManager/wpa_supplicant, а не приложение. Настроить только доверенные сети депо, запретить самовольное переключение на платный uplink. Установить `iwgetid` (wireless-tools). `sync.interface`, `sync.ssids`, `sync.start/end`, `timezone` определяют допуск к скачиванию. SSID не является криптографическим удостоверением точки доступа: WPA2/3 и TLS обязательны. На стоянке приложение требует выключенное зажигание. Начатая синхронизация может закончиться после конца окна.

`node.data=/var/lib/busradio/node`; файл `/etc/busradio/node.env` с `BUSRADIO_NODE_TOKEN=...`. Узел допускает один процесс на каталог. Проверка состояния — `status.json`, systemd journal и доставленные в сервер heartbeat. Сервер во время рейса необязателен; heartbeat отправляется вместе с ночной синхронизацией, поэтому это не live-система диспетчеризации.

Кэш по умолчанию 4096 MiB. Старые файлы автоматически не удаляются: это сохраняет старую активную версию и файлы, которые ещё играет поток. При переполнении новая загрузка отклоняется, прежняя программа остаётся. Очистку/архивацию делать на остановленном клиенте, сохраняя файлы активного и предыдущего манифестов. Очередь событий ограничена 20,000 файлами; регулярно проверять свободное место. Рекламные лимиты относятся к отдельному автобусу, резервируются до проигрывания и не заменяют серверный коммерческий биллинг.

## Нативный GPIO-FM: только после проверки стенда

Источник и инструкция сборки: https://github.com/ChristopheJacquet/PiFmRds . Нативный код/бинарник не перепакован в этот проект. Его лицензия GPLv3 и зависимость libsndfile должны быть соблюдены отдельно. Зафиксировать выбранную ревизию upstream при развёртывании; не обновлять работающий автобус без стендового прогона.

FM формируется аппаратным clock/PWM/DMA на GPIO4 (физический контакт 7). Выход содержит гармоники; без измерений, фильтрации и согласованного тракта нельзя считать его подходящим для эксплуатации. Первичную проверку проводить без антенны, по экранированной линии с подходящей развязкой/аттенюацией на измеритель/приёмник. Проверить допустимость частоты, мощности и режима по местным требованиям до излучения. Проект не выдаёт разрешения и не выбирает «свободную законную частоту» автоматически.

Java передаёт непрерывный WAV/PCM в stdin PiFmRds. Требуется установленный в `/usr/local/bin/pi_fm_rds` бинарник (root:root, каталог и файл не доступны на запись пользователю busradio). Для нативных аппаратных операций могут требоваться привилегии. Не запускать сетевой Java-процесс целиком от root.

Предусмотрен ограниченный helper:

1. После ревью установить `deploy/busradio-fm-wrapper` в `/usr/local/sbin/busradio-fm-wrapper`, root:root 0755; root-владение всех родительских каталогов.
2. Создать root-owned `/etc/busradio/fm-frequency` с одной отдельно разрешённой частотой в формате `NNN.NNN`; файл 0644, запись только root. Частота должна точно совпасть с `rf.frequency`, форматируемой Java до трёх знаков.
3. Проверить `visudo -cf deploy/busradio-rf.sudoers`, установить в `/etc/sudoers.d/busradio-rf`, root:root 0440. Helper допускает только фиксированную команду, stdin, имя станции и утверждённую частоту. Другие пути/аргументы запрещены. Сам helper не удостоверяет права на эфир.
4. Только в проверенной конфигурации задать `audio.mode=pifmrds`, `rf.enabled=true`, `rf.authorization=VERIFIED_BY_OPERATOR`, `rf.frequency=<утверждённая частота>`, `rf.executable=/usr/local/sbin/busradio-fm-wrapper`, `rf.useSudoHelper=true`.
5. Сервис по умолчанию имеет `NoNewPrivileges=yes`, поэтому sudo отключён. Явный lab drop-in `deploy/rf-lab-override.conf` снимает только это ограничение и открывает `/run/lock` для helper. Включать его только после ревью и аппаратной проверки; безопасность привилегированной границы важна даже без Интернета.

Не выдавать пользователю права менять helper, native binary, root-конфигурацию, sudoers или сервисный unit. Native child останавливается при завершении проигрывателя/сервиса; перед испытаниями отдельно проверить, что процесс и несущая действительно прекращаются при mute, отключении питания и ошибке. При RIFF-ротации примерно каждый час возможна короткая пауза. В штатном безопасном режиме backend пишет WAV, а не RF.

## Приёмка перед автобусом

Проверить ночное питание/SSID/часы, загрузку всего задания, обрыв Wi-Fi, заполненный диск, перезагрузку во время обновления, GPS stale/no-fix, оба направления и остановки, объекты за поворотом, проход рекламной зоны между песнями, mute при служебных объявлениях, восстановление очереди событий. Затем проверить реальные GPIO, нативный процесс и спектр с анализатором, не подменяя это программным WAV-тестом. Права на музыкальные произведения и рекламные записи обеспечиваются отдельно.

Источники API аппаратной части: https://www.pi4j.com/documentation/providers/gpiod/ ; https://www.pi4j.com/about/release-notes/ ; https://gpsd.gitlab.io/gpsd/gpsd_json.html .
