# busradio

Система бортового аудио на **Java 21 + Maven**: админка, ночная Wi-Fi-синхронизация, автономное воспроизведение и реклама объектов впереди автобуса с учётом направления маршрута.

**Версия 0.1.0 — работающий программный прототип, не сертифицированная автомобильная радиостанция.** Радиовыход выключен по умолчанию. Тесты не излучают радиосигнал. Проигрывание PCM не доказывает приём FM пассажиром.

## Что реализовано

- Русская веб-админка: медиатека, порядок песен, рекламные окна заданной длительности, кампании с геоточкой, маршруты, назначение бортам и публикация пакетов, отчёты.
- Импорт аудио через установленный FFmpeg в PCM16LE / 22050 Гц / mono. У каждого файла записывается основание использования. В демо — только синтезированные тестовые тоны.
- Подписанный Ed25519 манифест на автобус; SHA-256 каждого аудиофайла; докачка HTTP Range; атомарная активация только полного пакета; сохранение старого пакета при сбое; защита от отката подписанной версии.
- Ночное окно в заданном часовом поясе, белый список SSID, проверка Wi-Fi-интерфейса и маршрута до сервера. Для строгого исключения мобильного трафика дополнительно нужен системный firewall, пример приложен.
- Полностью локальный выбор рекламы: свежесть и точность GPS, направление, положение объекта впереди, расстояние, приблизительное время до объекта, срок кампании, ежедневное окно, приоритет, длительность ролика и ограничения повторов.
- GPSD либо свежий локальный JSONL в нормализованном формате `Eljah/buscrawl`. Импорт `routes.json`; направления `123:0` и `123:1` публикуются вместе. Переключение прямого/обратного направления происходит на борту.
- Pi4J 3.0.4: вход зажигания через подготовленный безопасный 3.3-вольтовый сигнал и LED. FM управляется отдельным нативным процессом `markondej/fm_transmitter`, а не переключением GPIO из Java.
- Аудиовыходы `null`, `wav`, `alsa`, экспериментальный `fm`. Один непрерывный поток в FM-процесс, без перезапуска перед каждой песней.
- Сохранение частотных ограничений рекламы и дисковая очередь отчётов с подтверждениями и дедупликацией после восстановления связи.

## Структура

```text
busradio-core/    модели, маршруты, геовыбор, формат buscrawl, подписи
busradio-server/  HTTP API, админка, FFmpeg, публикация и хранение
busradio-edge/    Wi-Fi-синхронизация, GPS, кеш, плеер, аудиовыходы
busradio-pi4j/    реальная интеграция GPIO через Pi4J / GpioD
busradio-tests/   38 детерминированных проверок, включая HTTP и PCM
config/          примеры конфигурации без секретов
deploy/          systemd, HTTPS reverse proxy, пример firewall
fixtures/        синтетические данные формата buscrawl
docs/            архитектура, API, оборудование, проверка и ограничения
```

Сервер использует JDK HttpServer, не Spring Boot. Серверная БД в этой версии — атомарные JSON-снимки и журнал; допускается один процесс на каталог состояния. Это упрощает демонстрацию, но не заменяет кластерную БД.

## Сборка Maven

Нужны **JDK 21**, Maven 3.9+, доступ к Maven Central. Для интеграционного теста нормализации установите FFmpeg. На Linux по умолчанию используется `/usr/bin/ffmpeg`; путь тестов переопределяется `-Dbusradio.test.ffmpeg=...`.

```bash
mvn --batch-mode --no-transfer-progress verify
```

Получатся:

```text
busradio-server/target/busradio-server-0.1.0-all.jar
busradio-edge/target/busradio-edge-0.1.0-all.jar
```

Оба файла имеют `Main-Class`; Pi4J и его плагины входят в Maven-сборку бортового `all.jar`.

**Что действительно проверено при подготовке:** JDK 21-компиляция core/server/edge/tests, 38 тестов без ошибок, синтаксис JavaScript через `node --check`. Maven отсутствовал, загрузка зависимостей была недоступна: Maven-сборка и компиляция модуля Pi4J в этой среде не выполнены. Физические GPIO, GPS-модуль и FM не испытывались. Навигация Chromium к локальному серверу была заблокирована политикой среды; успешный браузерный E2E не заявляется. Подробности: [docs/testing.md](docs/testing.md).

Для запуска без Maven и без Pi4J:

```bash
bash scripts/build-local.sh
java -jar dist/busradio-server-0.1.0-standalone.jar --demo
```

`build-local.sh` запускает те же тесты и собирает сервер + бортовой симулятор. На Windows `scripts/build-local.ps1` собирает эти два JAR без тестового прогона. Это не подмена аппаратного испытания симуляцией.

## Быстрый локальный запуск

В первом терминале, из корня репозитория:

```bash
# Пароль необязательно задавать: без переменной сервер напечатает случайный пароль при старте.
export BR_ADMIN_PASSWORD='set-a-long-random-password-here'
java -jar busradio-server/target/busradio-server-0.1.0-all.jar --demo
```

Откройте **http://127.0.0.1:8080**. При занятом порте задайте `BR_PORT`, например `18765`.

При первом `--demo` создаются условный маршрут, музыка и объявления-тоны, демоборт и приватный файл `var/server/demo-edge.properties`. Уже существующий каталог сервер повторно не инициализирует; сохраните выданный файл. Токен можно заменить через админку. Частота FM из демо не задаётся.

Во втором терминале, также из корня:

```bash
java -jar busradio-edge/target/busradio-edge-0.1.0-all.jar \
  --config var/server/demo-edge.properties --seconds 30
```

Для резервной JDK-сборки замените пути JAR на `dist/busradio-server-0.1.0-standalone.jar` и `dist/busradio-edge-0.1.0-simulator.jar` соответственно.

Борт скачает демопакет, запишет эфир в `var/demo-aircheck.wav` и сохранит события локально. В демо разрешена дневная синхронизация **только с loopback-сервером**, GPIO и FM выключены. Для немедленной отправки накопленных отчётов:

```bash
java -jar busradio-edge/target/busradio-edge-0.1.0-all.jar \
  --config var/server/demo-edge.properties --once
```

`--once` выполняет только синхронизацию при соблюдении сетевой политики; `--seconds` ограничивает длительность работы плеера, а не включает RF.

## Рабочий процесс администратора

Загрузите песни и ролики в «Медиатеке», укажите права использования. В «Плейлистах» добавьте песни и окна, например песня → песня → 60 секунд рекламы → песня. Остаток окна заполняется выбранной музыкой либо тишиной; рекламный ролик никогда не обрезается ради попадания в окно.

Импортируйте `routes.json` из buscrawl. Проверьте порядок и направления. **Остановки соединены хордами, а не реальными дорогами**: для точной привязки замените соответствующие направления дорожными полилиниями `SHAPE`. Назначьте геоточки кампаний, направления, радиусы и сроки.

Зарегистрируйте автобус, сохраните конфигурацию с токеном и публичным ключом. Нажмите «Опубликовать». Изменение редактора без новой публикации не меняет уже выпущенный пакет. В следующую разрешённую Wi-Fi-сессию борт получит полный пакет. Интернет в рейсе не нужен; собственный GNSS/GPSD нужен для актуальной георекламы.

## Raspberry Pi и FM

Полная настройка и границы применимости — [docs/hardware.md](docs/hardware.md). Важно: Pi4J обслуживает обычные входы/выходы, а сигнал FM получается аппаратным тактированием GPIO через внешний нативный генератор. Pure Java / `DigitalOutput.high()` не заменяют FM-генератор.

Поддержка библиотеки Pi4J на какой-либо плате не означает поддержку FM-метода на ней. Нативный upstream заявляет Raspberry Pi до 4 включительно и исключает Pi 5 / RP1. В проекте дополнительно ограничен запуск Pi 3, Pi 4 и Zero 2; это проверка модели, **не гарантия** сочетания ОС, ядра, DMA и выбранной частоты.

Не подключайте GPIO прямо к бортовым 12/24 В. Реальный эфир требует отдельной инженерной проверки спектра, помех, питания и применимых разрешений. Штатный systemd-пример не выдаёт привилегии для доступа к физической памяти и не превращает стендовый FM-трюк в автомобильное сертифицированное устройство.

## Дальнейшая эксплуатация

Используйте HTTPS, отдельные непривилегированные аккаунты, приватные каталоги/конфигурации и резервные копии серверного ключа. Потеря приватного ключа потребует повторного доверенного развёртывания публичного ключа на бортах. При утечке токена замените его в админке и на конкретном борту.

Версия 0.1 не содержит глобальный рекламный бюджет парка, биллинг, гарантии фактического FM-приёма, удалённое обновление JAR, автоматическую очистку кеша, RDS, стереокодер, HA, телеметрию в реальном времени или аварийный приоритет для штатных объявлений водителя. Эти границы перечислены явно в [docs/architecture.md](docs/architecture.md).
