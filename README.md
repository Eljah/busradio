# BusRadio

Java 21 + Maven: сервер с русскоязычной админкой, автономный бортовой проигрыватель, ночная Wi-Fi-синхронизация и геореклама. Pi4J управляет входами/индикатором; FM с GPIO создаёт отдельный нативный PiFmRds, которому Java передаёт непрерывный PCM-поток.

**Это проверяемый прототип для пилота, не сертифицированное бортовое радиоустройство. По умолчанию эфир отключён.** Демонстрация и тесты не обращаются к GPIO и не создают радиосигнал.

## Запуск демонстрации

Требуются JDK 21 и Maven; FFmpeg нужен для импорта MP3/FLAC/OGG и одного приёмочного теста.

```bash
mvn clean verify
java -jar target/busradio.jar demo var/demo 8080
```

Открыть `http://127.0.0.1:8080`, ввести случайный ключ администратора, напечатанный в консоли. Demo создаёт сервер, автобус, синтетический маршрут туда/обратно, два сгенерированных тона вместо чужих песен, рекламу и изменяющийся GPS. Результат проигрывания пишется в `var/demo/demo/node/captures/`. Папка demo должна быть новой; существующие рабочие данные не перезаписываются. Завершение: Ctrl+C. После завершения WAV получает правильную длину заголовка.

Без Maven переносимое ядро можно собрать установленным JDK:

```bash
bash scripts/build-local.sh
java -jar build/busradio.jar demo var/demo-local 8080
```

На Windows: `scripts\build-local.cmd`. Эта сборка **не содержит Pi4J**. Для Raspberry Pi:

```bash
mvn -Ppi clean verify
# Скопировать target/busradio.jar на бортовой компьютер.
```

Профиль `pi` добавляет настоящий `PiBoardIo` и Pi4J 3.0.4. Выбрана ветка Pi4J 3 для Java 21, а не требующая Java 25 ветка 4. Аппаратную работоспособность проверяют отдельно на конкретной плате/ОС.

## Сервер и админка

```bash
export BUSRADIO_ADMIN_TOKEN="$(java -jar target/busradio.jar token)"
java -jar target/busradio.jar server config/server.properties
```

Сервер по умолчанию слушает только loopback. Внешний доступ — через HTTPS reverse proxy. Ключи не кладут в Git, URL или общую конфигурацию. Сервер и бортовой клиент имеют отдельные режимы одного executable JAR; это не Spring Boot, а компактный Java HTTP server без зависимости от внешней БД.

Админка позволяет загрузить WAV/MP3/FLAC/OGG; собрать и переупорядочить плейлист; назначить рекламное окно после N целых песен; задать длину окна и максимум роликов; создать/изменить кампанию с координатами, датами, маршрутом, направлением, радиусом, зоной впереди автобуса, интервалом повторения и суточным лимитом; импортировать маршруты; зарегистрировать автобус и получить индивидуальный ключ; переназначить маршрут без смены ключа; просмотреть доставленные heartbeat и события.

Окна привязаны к числу песен, **не к фиксированным часам эфира**. Нет подходящего ролика — начинается следующая песня. Слишком длинный ролик не обрезается. Суточные ограничения действуют на один автобус, не на весь парк. Приоритет используется только при одинаковой близости подходящих объектов.

## Автобус

Отредактировать `config/node.properties`: URL HTTPS-сервера, bus ID, разрешённые SSID депо, расписание, часовой пояс, GPS и GPIO. Индивидуальный ключ выдать в админке:

```bash
export BUSRADIO_NODE_TOKEN='индивидуальный-ключ-из-админки'
java -jar target/busradio.jar node config/node.properties
```

Ночью, в разрешённой Wi-Fi-сети и при выключенном зажигании клиент получает манифест. Неизменившиеся файлы не качаются повторно, частичные файлы докачиваются HTTP Range. SHA-256, длина и формат проверяются до атомарного переключения версии. При обрыве/ошибке новая программа не становится активной; остаётся прежняя.

Днём проигрыватель, GPS и подбор рекламы работают без сервера. События сохраняются локально и удаляются только после подтверждения сервера. Дубли событий сервер обрабатывает идемпотентно. `COMPLETED` означает передачу PCM выбранному backend, **не доказательство приёма радиосигнала пассажирами**.

GPS берётся из локального gpsd; для стенда есть источник JSON-файла. Рекламу подавляют устаревшие (>30 с), будущие (>5 с), неточные (>50 м) координаты, выход с маршрута и несогласованное направление. Во время движения направление выбирается по курсу и геометрии; на остановке сохраняется последнее, а при старте используется назначенное направление. Перекрывающиеся маршруты и развороты требуют отдельной полевой настройки — полноценного HMM map-matching здесь нет.

Геоподбор: активная кампания → нужный маршрут/направление → свежий GPS → близость к маршруту и объекту → объект впереди → ролик помещается → лимиты повторения → ближайший подходящий объект. Проверка повторяется перед каждым роликом. Музыка не обрывается ради геозоны, поэтому узкую зону можно проехать между окнами.

## Интеграция с Eljah/buscrawl

Адаптер написан по реально просмотренным `RouteTopology.java`, `RouteMapper.java`, `BusNaviRealtimeClient.java` и `docs/navi-raw-source.md`, ревизия `0411483d040356a9a53a7ff254d4bd4b34f021b0`:

https://github.com/Eljah/buscrawl/tree/0411483d040356a9a53a7ff254d4bd4b34f021b0

Вкладка «Маршруты и автобусы» принимает оригинальный `src/main/resources/routes.json`: `nbusstop` = имя/долгота/широта, `bus` = метаданные, `route` = ID маршрута/ID остановки/направление/порядок. Конвертация без сервера:

```bash
java -jar target/busradio.jar import-buscrawl routes.json converted-routes.json
```

**Остановочные цепочки — не точные дорожные полилинии.** Для уверенного геотаргетинга на поворотах надо загрузить уточнённую геометрию через редактор маршрута. `navi-route-map.json` overlay в этой версии ещё не импортируется автоматически. Адаптер координат `Buscrawl.position` умеет JSONL-схему crawler, выбирает именно `sourceTimestamp`, переводит км/ч в м/с и проверяет идентификатор автобуса. Это утилита преобразования, а не подключённый по умолчанию live-клиент: штатный бортовой источник — gpsd. Исторические координаты не превращаются в «свежий GPS».

## FM непосредственно с GPIO

Это именно GPIO-генерация без отдельного FM-модуля, но не цикл `high()/low()` на Java. Аппаратные clock/PWM/DMA использует [PiFmRds](https://github.com/ChristopheJacquet/PiFmRds); Java занимается звуком, событиями и запуском нативного процесса. RF-backend этой версии допускает Pi 3, Pi 4 и Zero 2; Pi 5 не заявлен. GPIO4 (физический pin 7) зарезервирован для RF и недоступен обычным Pi4J-входам.

`audio.mode=wav` — безопасный штатный исходный режим. `audio.mode=pifmrds` требует явных `rf.enabled`, `rf.authorization`, частоты и установленного нативного backend. Подробности ограниченного привилегированного helper, сигнальных входов, безопасного стенда и развёртывания: [docs/OPERATIONS.md](docs/OPERATIONS.md). PiFmRds не включён в JAR и устанавливается отдельно с соблюдением его лицензии.

Не подключать антенну и не включать в автобусе «просто потому, что свободная частота». Требуются проверка местных разрешений/параметров, анализ спектра и подавление гармоник, экранированный тракт для первичной проверки. Программный флаг не делает устройство соответствующим требованиям. GPIO не является автомобильным 12/24-вольтовым входом.

## Проверки и границы готовности

Приёмочный набор `SystemTest` запускается Maven в фазе `test`; результаты — `build/test-results.json` и XML. Покрыты реальный HTTP server, авторизация, Range, SHA-256 и отказ атомарной установки, перезапуск лимитов, направление, истечение кампаний, потеря GPS, офлайн-проигрывание после остановки сервера, повторная доставка событий и WAV/MP3. CI собирает portable и Pi4J-профили, но не излучает RF.

Локально выполнены JDK-сборка и 31 приёмочный тест без ошибок. Также успешно завершены обе Maven-сборки на GitHub Actions: portable и `-Ppi` ([проверенный запуск](https://github.com/Eljah/busradio/actions/runs/36984776115), код ревизии `dc04b8de383f1a6b237b2c904b86e0b8a97716df`). Это не аппаратная сертификация и не тест на реальной Raspberry Pi. Аппаратный Pi4J, нативный FM, качество приёма и реальные маршруты требуют стенда/полевого прогона.

Сервер — один процесс, JSON snapshots + файлы, с блокировкой каталога. Нет HA, общего рекламного бюджета, автоматической очистки медиакэша, управления Wi-Fi-паролями и полной телеметрии парка в реальном времени. Кэш ограничен, переполнение не заменяет работающую программу неполной. Wi-Fi-окно проверяется при старте синхронизации, начатая загрузка может закончиться после его окончания. RF-процесс перезапускается примерно каждый час для ограничения WAV-потока; возможна короткая пауза. Резервирование рекламного лимита до воспроизведения консервативно при отключении питания и не является биллинговым отчётом. Нужны лицензии/права на фактически распространяемые песни и рекламу.
